# План реализации по SDD

Каждый этап начинается с тестов или проверяемых критериев из `acceptance.md` и заканчивается демонстрируемым вертикальным срезом.

## Этап 0. Согласование спецификации

- [ ] Подтвердить `spec.md`, особенно границы local-first MVP.
- [ ] Утвердить оригинальное визуальное направление и образ хранителя.
- [ ] Зафиксировать спорные решения отдельными ADR при появлении альтернатив.

Результат: спецификация получает статус `Approved`.

## Этап 1. Каркас и дизайн-система

- [ ] Создать Next.js + TypeScript приложение и тестовый контур.
- [ ] Добавить маршруты: Главная, Библиотека, Сейчас читаю, История, Статистика, Книга.
- [ ] Определить tokens палитры, типографики, размеров, теней и движения.
- [ ] Реализовать адаптивную навигацию и app shell.
- [ ] Добавить статичные оригинальные иллюстративные assets первого прохода.
- [ ] Настроить PWA manifest, service worker и reduced-motion режим.

Проверка: навигация работает на 360 px и desktop; axe не находит критических нарушений.

## Этап 2. Локальная предметная модель

- [ ] Реализовать схемы Zod и Dexie.
- [ ] Добавить миграции и repositories для книг, чтений, обложек и настроек.
- [ ] Реализовать статусы, форматы, любимую отметку и ручное добавление.
- [ ] Покрыть инварианты и переходы unit/integration тестами.

Проверка: AC-01 и AC-03.

## Этап 3. Визуальная библиотека

- [ ] Реализовать режим «Корешки».
- [ ] Реализовать режим «Обложки».
- [ ] Добавить ручной порядок, drag-and-drop и доступные команды перемещения.
- [ ] Добавить поиск, фильтры и временные сортировки.
- [ ] Реализовать извлечение/резервный выбор темы корешка.

Проверка: AC-04, AC-05, AC-06, AC-07 и mobile visual regression.

## Этап 4. Автозаполнение книг

- [ ] Определить provider interface и нормализованный контракт.
- [ ] Подключить Google Books.
- [ ] Подключить Open Library как fallback.
- [ ] Добавить объединение дублей и выбор обложки.
- [ ] Добавить загрузку собственной обложки.
- [ ] Реализовать состояния сети, ошибок и ручной fallback.

Проверка: AC-02 и повторная проверка AC-03.

## Этап 5. Чтение и дневник

- [ ] Реализовать «Сейчас читаю» и переходы статусов.
- [ ] Реализовать записи чтения и даты.
- [ ] Реализовать десять стилизованных звёзд с клавиатурным управлением.
- [ ] Реализовать утверждённые формы fiction/nonfiction.
- [ ] Реализовать перечитывание и сравнение записей.
- [ ] Добавить автосохранение и свободный комментарий.

Проверка: AC-08, AC-09, AC-10 и AC-11.

## Этап 6. Главная, история и статистика

- [ ] Собрать уютную главную страницу из реальных локальных данных.
- [ ] Реализовать хронологию завершённых чтений.
- [ ] Реализовать расчёты и визуализации статистики.
- [ ] Добавить годовой фильтр и корректные пустые состояния.

Проверка: AC-12 и visual regression ключевых страниц.

## Этап 7. Надёжность данных

- [ ] Реализовать версионированный JSON export.
- [ ] Реализовать безопасный import с валидацией и предпросмотром.
- [ ] Добавить предупреждения об удалении и локальном хранении.
- [ ] Проверить офлайн-редактирование и кэш app shell.

Проверка: AC-13 и AC-14.

## Этап 8. Полировка и релиз кандидата

- [ ] Добавить оригинальные финальные иллюстрации и анимации.
- [ ] Проверить интерфейс на реальном телефоне и компьютере.
- [ ] Выполнить полный e2e, accessibility и visual regression прогон.
- [ ] Проверить 1 000 тестовых книг и размер резервной копии.
- [ ] Подготовить инструкцию по запуску, использованию и backup.

Проверка: AC-01—AC-15 проходят; критерии успеха из `spec.md` выполнены.

## После MVP

Следующая отдельная спецификация должна описать приватную синхронизацию. Она не должна менять локальную модель пользователя без плана миграции и разрешения конфликтов.
